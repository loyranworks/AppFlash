# macOS 全屏焦点与查询延迟修复

用户提供 0.1.11 诊断：ChatGPT.app 多次 activate 约 1.21s 超时，窗口已显示但键盘焦点未到达；其他多款应用 snapshot 反复约 155–170ms。

## 已验证的边界

- 未直接控制 Codex/ChatGPT；电脑操作工具此前明确禁止操作宿主应用。依据用户日志及独立测试窗口排查。
- 标准双全屏窗口四轮实际键盘接收通过；这不证明用户目标应用的特殊焦点行为已复现。
- 未变化的未知 CG 辅助图层导致旧版四次 warm snapshot 为 161–164ms，性能回归用例失败。
- 自有窗口保持 CGWindowID、orderOut/orderFront 重建 AX 引用后，0.1.11 同次 activate 约 1.2s 超时；修复后双应用四轮实际输入通过。

## 改动

- 快捷键路径只做有界公开/已知根校验；私有 token 补充扫描移至空闲小片段，保留进度、有限总预算，IPC 操作期间不重入，无任务不维持定时器。
- 保存已确认窗口的精确 CGWindowID；AX 引用失效后，仅在同 PID、同 ID 的有效标准/最小化窗口中重新定位，保留原逻辑 ID。
- 隐藏恢复后仍确认应用与精确窗口；可见但没有焦点时最多补两次 AXFrontmost / 精确置前，共用原截止时间，不延长操作、不积压后续按键。
- 日志补充激活请求结果、前台/焦点 PID、各 AX 写入结果、重定位及补请求计数；不记录标题或输入内容。
- 固定签名、Navy 贴边、Windows 窗口控制策略不改。
