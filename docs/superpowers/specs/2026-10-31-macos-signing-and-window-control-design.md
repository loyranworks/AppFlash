# macOS 稳定签名、窗口循环及全屏切换

## 目标与授权

用户要求合并完成并验收后提交 GitHub、发版：固定免费自签名证书；同应用所有窗口逐一前台后全部收起并循环；全屏独立桌面中的贴边提示及跨应用切换；macOS 贴边提示改为圆角原生 Liquid Glass。用户已选择跳到目标窗口所在桌面并保留全屏状态，循环结束遇到全屏时隐藏应用以保留全屏，已允许本轮在 Mac mini 使用 CGEvent 发送临时测试组合键。

## 当前证据

- 基线为 v0.1.7 / d23262c，28 项 JavaScript 与 17 项 Rust 测试通过，工作区干净。
- 当前 ad-hoc 主应用的 designated requirement 是具体构建的 cdhash，版本间不同。MBP 0.1.7 重新添加辅助功能授权后已恢复，证明此前快捷键与权限问题的边界。
- Swift 原生激活在 AXMain 设置成功时跳过 AXRaise；AXMain 不等同于目标窗口获得键盘焦点。仍需用多窗口实际应用复现。
- 现有循环按系统瞬时 active 判断结束，当前窗口位于枚举末尾时可能过早全部最小化；系统焦点异步刷新也可能使循环重复。
- 提示窗口只有置顶和不可聚焦，没有跨 Spaces / 全屏辅助窗口配置。

## 方案与取舍

沿用现有 Rust / Swift / Tauri 架构。固定自签名是用户选定的免费方案；Developer ID 与 Apple 公证不属于本次范围。不能以放宽到仅匹配 bundle ID 的签名规则代替证书身份。

优先使用公开 AppKit / Accessibility API。提示窗口先配置跨桌面、全屏辅助及 macOS 13+ 的跨应用辅助行为；若现有 NSWindow 仍不能进入全屏 Space，则用真正的非激活 NSPanel 承载同一提示内容。比重写提示 UI 小，也能保留现有事件和排版。

激活必须同时验证目标应用与目标窗口。先测试 AXRaise / 焦点属性及公开应用激活操作；若跨 Space 的精确激活确实需要非公开 API，将其限制在独立的 macOS 兼容层，以原始窗口引用获得真实窗口 ID，动态检测可用性并提供明确失败，禁止通过标题或屏幕坐标猜测窗口。此兼容分支是否必需由复现决定。

Windows 原生操作和现有循环行为保留；macOS 的循环策略可单独实现，避免因 macOS 焦点时序改变 Windows。

## 固定签名与秘密存储

生成一次长期有效的自签名 Code Signing 证书和私钥，后续正式版本复用。应用标识保持 `local.appflash.desktop`，签名身份固定为证书锚点加代码标识；原生组件也采用同一证书、固定代码标识。私钥不进入源码、日志、发行包或普通附件。

持久备份放本机受限的签名目录，供 CI 使用的加密证书和密码保存到 `loyranworks/AppFlash` 的 GitHub Actions Secrets。macOS runner 只在临时钥匙串导入，任务结束清理临时钥匙串。公开仓库只保存公有证书/指纹和验签规则。原 Tauri 更新签名密钥与公钥不变。

Tauri 的自动证书枚举仅识别 Apple 证书名称前缀，因此本方案自行预先导入真正的自签名证书，使用证书指纹提供 `APPLE_SIGNING_IDENTITY`，不伪装成 Developer ID。导入工具保存并在结束时恢复钥匙串搜索列表，不修改系统全局根信任；应用身份校验绑定固定证书，不要求最终用户安装根证书。

首次从 ad-hoc 迁移到固定证书仍需授权一次。本次必须先安装测试构建 A 并授权，在同一路径替换成内容与版本不同、由同一证书签署的构建 B 后，不修改授权列表即可执行真实窗口操作。对比两个构建的 designated requirement、指纹、AX 状态和实际操作结果；只有这一实测通过才宣称升级保留授权。自签名不代表 Gatekeeper 或 Apple 公证通过。

## 多窗口循环语义

以窗口真实引用稳定标识窗口，维护本轮已成功置前的集合。进入目标应用时从稳定顺序开始；如果目标应用已有前台窗口，该窗口算本轮已前台，随后访问其他窗口。所有现存窗口均已前台后，下一次按键才全部最小化；再次按键开始新一轮恢复与逐窗置前。

窗口重新排序不改变本轮顺序；新窗口加入本轮，关闭窗口移除；切换目标应用重置本轮。焦点更新稍晚不导致重复访问或过早最小化。操作失败不消耗本轮进度。外部手动切换窗口时，以实际前台窗口重新协调本轮状态。

## 全屏与桌面

按住前缀时，提示在当前全屏 Space 显示，保持不抢焦点、鼠标穿透，释放后消失。普通桌面与多个显示器沿用鼠标所在屏幕定位。

跨应用激活跳到目标窗口所在 Space，不搬移窗口、不更改系统桌面偏好、不退出源窗口或目标窗口的全屏。全屏窗口不应因为恢复代码无条件写 AXMinimized=false 而失败。

循环结束时，普通窗口全部最小化；若目标应用包含全屏窗口，则隐藏该应用作为本轮收起动作，保留全屏状态与 Space。下一轮先取消隐藏，再恢复逐窗置前。正常跨应用切换始终保留全屏。

## 原生玻璃外观

应用 `frontend-design` 指导，沿用现有应用图标、字母与用户配色。macOS 26+ 使用公开 `NSGlassEffectView`，不以 CSS 模糊冒充 Liquid Glass；更早系统用 `NSVisualEffectView`。玻璃视图必须以原提示内容为 contentView，WebView 本身透明，避免旧的方形渐变和模糊层盖住原生材质。

设计为窄竖向圆角浮层，约 24pt 圆角、距屏幕边缘约 12pt，保留轻量原生阴影。图标、字母左右对齐，按应用数量收缩高度，保留密集列表布局与鼠标穿透。用户明确要求保留竖向主线、每行连接线、沿主线移动的流光及按键命中反馈，作为 AppFlash 的辨识特征。流光仅在提示显示时播放，减少动态效果设置仍应受到尊重。

2026-10-31 用户最终确认采用 B 清透玻璃和工作室 VI 正式色 Navy `#244b70`，保留主线、连接线和流光。流光采用 Snow `#f8fbff` 与 Sky `#e6f0fa` 高光。用户自定义 accent 保留。中性色和背景由原生材质随系统浅/深色适配；系统减少透明度设置应得到尊重。macOS 字体采用系统字体。VI 扩展不修改。

Windows 提示外观与材质路径保持现状。验收必须在普通桌面与全屏 Space 中看实际原生效果，确认四角透明、布局无裁切、玻璃没有被不透明 WebView 背景覆盖。

用户随后要求整体比例可调：设置页增加百分比输入与滑杆，统一缩放提示背景、图标、字母、间距、圆角、阴影留白及原生窗口尺寸，不改变屏幕边缘锚点与垂直居中。旧配置缺省为 100%，预览提供 80% 参考；范围暂按 50–150%，输入与滑杆同步，保存沿用现有配置事务与校验。macOS 的原生材质与 Windows 的原效果都遵守整体缩放，新增字段向后兼容旧配置。

## 验收与发布门槛

1. 循环测试覆盖从末尾窗口开始、窗口顺序变化、焦点滞后、新建/关闭、失败不推进及最小化后的下一轮。
2. Mac mini 用真实应用多窗口和独立测试窗口跑两轮完整链路，CGEvent 只发送临时组合键，测试完恢复原配置。
3. 全屏 Space 中实际看见原生玻璃提示，并从普通窗口切入全屏、从全屏切到其他普通/全屏应用，核对目标焦点和全屏状态；Finder 不作为唯一验收目标。循环结束时全屏应用隐藏，下一轮取消隐藏且不退出全屏。
4. 固定证书 A→B 替换后的实际授权保留测试通过。
5. 完整测试、格式、版本、签名身份与严格签名检查通过，再合并为一个正式版本。正式工作流必须要求固定证书，禁止静默退回 ad-hoc。
6. GitHub Windows x64、macOS ARM / Intel 和 publish 全部成功后，匿名下载并核对摘要、更新签名及清单，记录实测范围。未完成的必要验收不得包装为通过。
