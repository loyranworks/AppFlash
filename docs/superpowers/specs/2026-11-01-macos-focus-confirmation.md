# macOS 精确窗口激活与焦点误报

用户已授权继续修复、在当前仓库验证并统一提交发版。本轮不改变多窗口循环、全屏隐藏、Navy 玻璃或签名策略，不扩展 VI。

## 证据与契约

- MBP 的 ChatGPT 已可直接键盘输入，但 0.1.13 日志仍在 1.2 秒后报错：前台 PID 正确、系统级焦点 PID 为 0。不能将系统查询缺值等同于窗口没有激活。
- Mini Safari 切换期间，系统 `AXFocusedApplication` 返回 `.noValue`，应用本地的 `AXFocusedWindow` 已匹配。后者也可能在桌面动画期间提前出现，因此不能单独作为成功依据。
- 激活契约是目标应用的精确窗口到达前台和当前桌面；不选择网页输入框，不声称已检测到编辑光标，也不点击或遍历用户内容。
- 系统提供有效焦点时，继续要求 PID 和精确 AXWindow 匹配。系统明确缺值或不支持时，才允许同时用前台 PID、应用 AXFrontmost、精确本地 AXFocusedWindow、未隐藏/未最小化和精确 CGWindowID 在屏幕上确认窗口。权限、忙碌、失效引用和明确不同的焦点不走降级。
- 日志区分系统确认和应用窗口确认，并记录状态码；不把推断出的 PID 填成系统观测 PID。
- 保留当前总截止时间、最多两次修复与快捷键丢弃忙碌请求策略。性能优化必须有真实键盘接收与位置保持验证，不能只提前打印成功。

## 验收边界

独立源代码测试窗口：注入系统焦点缺值，仍须在精确窗口接收键盘并保留插入位置；负例覆盖错误窗口、其他桌面、硬错误与失效目标。Mini Safari/Hermes 真实全局键与输入位置复测。锁屏后首次操作已有一次短锁屏基线，无明显额外迟滞，不能推广为 MBP/长时间锁屏结论。宿主 Codex/ChatGPT 不通过其他途径绕过电脑工具限制测试。
