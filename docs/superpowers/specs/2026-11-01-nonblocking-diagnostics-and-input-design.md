# 非阻塞日志与跨平台按键入口

用户授权修复托盘暂停提示、日志阻塞及 Windows 防积压，验证后发布；明确保留原窗口切换逻辑。长期架构只调研并提出建议，本轮不改写窗口算法或进行大规模平台重构。

选择共享有界后台日志队列与已有原子按键 permit，而不是在切换线程继续同步写盘或复制一套 Windows 专属门禁。日志队列 128 条，单条沿用现有上限；记录只做非等待提交，磁盘慢或导出持锁不阻塞切换，满队列丢弃并累计报告。时间取事件产生时刻；导出按 FIFO 等待已接收事件，保留本地显示时区、七个 UTC 日期、每日 2 MiB、脱敏与本机存储规则。退出只做有截止时间的尽力排空，不无限等待磁盘。后台维护仍定期执行。

把 macOS 已验证的 RAII permit 改为两端共用：从快捷键回调取得 permit，一直持有到执行结束；忙碌按下不进入队列、不重放，完成后的新按键照常接收；释放事件可清理原状态。Windows 仍使用 switching::Cycle，macOS 仍使用 macos_cycle::Cycle；不改变单/多窗口顺序、选择、激活、最小化和全屏隐藏策略。

托盘 paused-changed 事件同时刷新底部状态。未保存提示优先，手动暂停与草稿暂停保持独立。覆盖中英界面、干净和未保存状态。

验证重点：阻塞存储时日志提交仍完成、队列满时内存有界和丢弃可见、导出包括已接收日志、退出有界；Windows 编译分支真实入口使用 permit、慢执行下连续按键不积压；原窗口算法文件保持逐字节相同。Windows 实机无法在 Mini 代替，应清楚区分自动化、CI 和 macOS 实机证据。
