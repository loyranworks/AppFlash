# 多屏全屏收起：停止连续试切

用户复现：MBP 内屏上的 Hermes 全屏，接入外接屏后按 Control+H，Hermes 未收起，外屏应用连续跳转。用户已明确这是按快捷键后发生，沿用既定的“保留全屏，隐藏应用代替最小化”。

10:22:36–10:23:10 的 0.1.13 日志中，七次 Hermes 收起均尝试多个其他 PID，约两秒失败；busy 按键被丢弃，未见互斥队列等待。0.1.14 仍有此候选循环。确认的实现缺陷是一次操作连续激活多个候选；多屏下还错误要求源全屏窗口从所有屏幕消失，源应用失活但仍在另一屏可见时会继续尝试。

## 方案与选择

- 只增加插屏冷却：只能减少插屏当下触发，无法修正稳定多屏状态的错误判定，不采用。
- 沿用隐藏语义，按应用失活和最终真实 AXHidden 判定；一次准备最多激活一个候选：本轮采用，属于修复原语义。具体选择顺序由实现者确定为优先其他已可见窗口，之后使用有效缓存和现有应用顺序。
- 自动移动窗口、退出全屏或切换系统桌面设置：违反已确定的保留全屏要求，不采用。

## 最小改动

源应用已明确不在前台时，准备步骤直接返回，让最终隐藏动作核对 AXHidden；不要求当前前台有标准窗口，保留外屏 Finder 桌面情形。源应用仍在前台时，先只读选择候选：优先当前屏幕上最靠前的其他有效标准窗口，减少改变外屏已有画面；无可见目标时再考虑有效缓存和原候选顺序。排除本次所有待收起进程。仅激活选定窗口一次，并在截止时间内同时确认精确目标、前台 PID 和源应用失活；失败直接返回错误，不继续激活别的应用。

“允许尝试隐藏”与“主动切离后刷新清单”分开：准备函数返回是否主动激活了目标，只有主动激活且视觉切换完成才重读窗口清单。最终隐藏仍由既有 setHidden 的状态读取确认，不能把失活误当已隐藏。未知的其他 Space 首次 AX 根仍属于既有兼容性边界，不能宣称完整发现。

## 任意数量显示器

按当前 Quartz 全局坐标将每个窗口映射到所有相交活动显示器，不硬编码内屏、外屏或屏幕数量。主动切离后要求目标实际上屏；只有目标所在显示器上的源全屏窗口需要离屏，其他显示器上的源全屏窗口允许仍可见。目标窗口跨多屏时检查其覆盖的全部屏幕，多个源全屏窗口逐个检查。负坐标、上下布局、不同分辨率和镜像按同一坐标逻辑处理，不混用 AppKit/AX 坐标或重复乘缩放系数。

读取候选前保存本次显示器逻辑布局，激活前及确认期间复核；布局缺失或改变就停止当前操作并提示重新按键。枚举顺序改变不算布局变化，不添加后台轮询或延迟重放。每次判定重读当前布局和 WindowServer 记录，不缓存窗口位置。

SDK 定义源窗口记录省略可选 kCGWindowIsOnscreen 键即表示离屏；只有完整记录缺失、存在但类型错误的状态或无效/过期几何是未知。不得将正常省略键误判为无法完成桌面切换。

记录源 PID、显示器数量、选定目标 PID/CGWindowID、确认或失败阶段，不读取用户窗口标题或内容。未知状态保守失败，不把缓存为假当成实际状态，不添加延迟执行队列。

## 验证边界

Mini 只读确认只有一块活动显示器。非 GUI 回归运行真实生产准备函数，仅替换外部系统元数据与激活动作，覆盖候选失败不串行试切、失活但仍可见、可见窗口优先和状态不一致。随后用完全自有窗口做真实全屏隐藏/恢复、单/多窗口、缺值和引用重建回归。物理双屏热插拔仍需 MBP 验证，不能把注入元数据测试说成真实插屏实测。
